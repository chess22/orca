# DEV2 機能統合・バージョン履歴仕様

## 目的

既存ブランチで実装済みの機能を、公式 Orca を土台とする `Orca Dev 2` へ段階的に統合する。各段階のバージョン、元コミット、移植コミット、テスト、ビルド、実機確認を本書で履歴管理する。

## 対象と土台

- アプリ名: `Orca Dev 2`
- Bundle ID: `com.stablyai.orca.dev2`
- userData: `orca-dev2-app`
- CLI: `orca-dev2`
- 最初の公式土台: `v1.4.183`
- 作業ブランチ: `chess22/DEV2`

## バージョン規則

DEV2バージョンは `<公式版>-dev2.<段階番号>` とする。

```text
1.4.183-dev2.0  DEV2独立起動基盤
1.4.183-dev2.1  画面分割サイズ管理
1.4.183-dev2.2  セッション再起動耐性
1.4.183-dev2.3  履歴専用セッション復元
```

同じバージョンで異なる内容を作らない。修正も新しい段階番号にする。公式土台を更新した場合は段階番号を`0`へ戻す。

## 統合原則

- 1バージョンにつき、ロールバック可能な1機能群だけを入れる。
- 現段階のコミット、テスト、ビルド、起動確認、履歴更新が完了するまで次へ進まない。
- 公式版に同等機能があれば再適用せず、`公式版で充足`と記録する。
- 元コミットを直接適用できなければ、最新版へ移植した新しいコミットを作り、両方のSHAを記録する。
- 本番OrcaとDEV2のuserData、runtime、daemonを混在させない。

## 段階計画

### `1.4.183-dev2.0`: DEV2独立起動基盤

- 専用アプリ識別子、userData、runtime、daemon
- `orca-dev2` CLI
- macOS、Windows、LinuxのDEV2成果物名
- 本番Orcaとの同時起動

### `1.4.183-dev2.1`: 画面分割サイズ管理

元コミット候補:

- `d22fee63b5`: pane幅・比率取得、split時のサイズ指定
- `1b77a4f1e0`: headless splitの`sizePx`永続化
- `6534255b8c`: 作成後のpane比率変更
- `74bd3debd4`: 複数window notifier向けresize dispatch維持（単一notifierの本土台では適用不要）

確認項目:

- pane比率の取得と変更
- split時の比率またはpixel指定
- 再起動後の比率復元
- local、folder workspace、SSHの互換性
- macOS、Linux、Windowsの互換性

### `1.4.183-dev2.2`: セッション再起動耐性

元コミット候補:

- `1d3b02de9f`: packaged GUIの`SIGHUP`耐性
- `f75061bee0`: daemon生存セッションの入出力再接続
- `6fcee40cef`: 復元terminalへの直接アクセス時の再接続

### `1.4.183-dev2.3`: 履歴専用セッション復元

元コミット候補:

- `82492fbbac`: agentを再開せずarchived terminalを復元
- `b743a37055`: history-only terminalを保持
- `cd1d0fd584`: shellを起動せずcheckpointを表示

`v1.4.183`の同等機能を先に比較し、不足分だけ移植する。

## 段階ごとの手順

1. 公式土台とDEV2のHEADを記録する。
2. 元コミットの差分、依存関係、公式版の同等実装を確認する。
3. 1機能群だけを移植する。
4. `git diff --check`、対象テスト、型チェックを実行する。
5. DEV2バージョンを付けてアプリをビルドする。
6. 本番Orcaを止めず、DEV2をバックグラウンド起動する。
7. runtime、graph、userData、対象機能を確認する。
8. 履歴表を更新し、完了版をコミットする。

## 完了条件

- 作業コミットが記録されている
- `git diff --check`が成功
- 対象テストが成功
- 型チェックまたは対象ビルドが成功
- アプリ表示バージョンが予定値と一致
- runtimeとgraphが`ready`
- 本番OrcaとDEV2のruntime IDが異なる
- 表示変更は実画面確認まで完了

## ロールバック

- 直前の完了版アプリを残し、次段階で上書きしない。
- schema変更前はDEV2のuserDataだけをバックアップする。
- 本番OrcaのuserDataをDEV2の復旧に流用しない。
- 強制resetではなく、revertまたは修正コミットで履歴を残す。
